# Phase 5: 记忆压缩 — 语义浓缩

## 目标
将簇内多条相关记忆合并为一条浓缩记忆，减少活跃池数量，保留决策骨架。

## 设计原则
1. **原始不删** — 压缩版用于快速检索，原始版进归档
2. **关键字段保留** — 游戏名、Bug描述、数值、决策原因永远不压缩
3. **只压缩表述** — 冗余表述去除，保留语义核心
4. **关联保留** — 压缩后记忆链接到原始记忆ID

## 压缩策略

### 策略1: 簇内合并（主要）
同一簇内，内容高度相似的记忆合并为一条：
```
记忆A: "贪吃蛇碰撞用AABB判定"
记忆B: "贪吃蛇碰撞边界条件Bug"
记忆C: "贪吃蛇碰撞修复：加边界检查"
→ 压缩: "贪吃蛇碰撞系统：AABB判定，边界条件Bug已修复"
原始A/B/C → 归档
```

### 策略2: 时间线合并（辅助）
同一话题的多条时间线记录合并：
```
记忆A: "2026-05-28 塔防v2开始设计"
记忆B: "2026-05-29 塔防v2素材切换完成"
记忆C: "2026-05-30 塔防v2部署上线"
→ 压缩: "塔防v2：05-28启动→05-29素材切换→05-30上线"
```

### 策略3: 重复消除（辅助）
内容完全重复或高度雷同的记忆去重：
```
记忆A: "修复了碰撞Bug"
记忆B: "碰撞Bug已修复"
→ 保留A，B归档
```

## 压缩质量保障

| 检查项 | 方法 |
|--------|------|
| 信息完整性 | 压缩后记忆必须包含所有原始记忆的游戏名、Bug描述 |
| 可追溯性 | 压缩后记忆必须记录来源ID列表 |
| 可回滚 | 归档的原始记忆可随时恢复到活跃池 |
